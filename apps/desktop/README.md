# Site Factory desktop

Russian Tauri 2 shell for the explicitly labelled local demonstration. It uses the existing deterministic model and publication adapters; no cloud account, real model, DNS or hosting acceptance is implied.

Use Node 24.21.0 or newer in the 24 LTS line for development and bundled sidecars. From the repository root, install the lockfile with `npm ci`, install the pinned Playwright Chromium with `npm exec playwright install chromium`, then run `npm run tauri:dev`. The launcher writes ignored `.local-state/desktop-dev.json` using its own Node executable and this checkout's compiled worker. Rust accepts this trusted configuration only in debug builds. UI requests cannot choose paths, executables, roles, URLs or shell arguments.

The native application stores local state in Tauri's app-local-data directory. An OS file lock permits one controller. A private stdin/stdout pipe carries bounded versioned requests; stderr carries diagnostics. EOF checkpoints active jobs; the native owner waits 15 seconds before terminating the child. On Windows a kill-on-close Job Object owns Node and its Chromium descendants. A dead worker starts again on the next request; interrupted leases remain fenced until their 120-second expiry. Interrupted jobs resume on application start; explicitly paused batches require Continue. Legacy JSON sources remain unchanged after validated SQLite migration and reopen.

Custom commands are enrolled with `AppManifest::commands` and the `desktop-dispatch` permission is granted only to the local main webview. Generated files are never loaded in that webview. Preview images are read by site/revision/width through private checkpoints and RevisionRepository; no arbitrary file-read command or public screenshot service exists. Interactive preview opens separate sandboxed Chromium with read-only generated files and no native bridge.

Release lookup is fixed to `resource_dir/runtime/node(.exe)`, `runtime/worker/stdio.js`, and `runtime/{templates,references}`. Release resource assembly, bundled browser/runtime installation and signed platform installers belong to packaging Task 14; this task does not claim a self-contained distributable. The dev launch is tested on Windows 10, which is not the approved Windows 11+/macOS 14+ acceptance matrix.

## Checks

- `npm run typecheck`, `npm run build`
- `npm test`: adapter/runtime/protocol tests (real Chromium required)
- `npm run test:e2e`: React in Chromium with a test-only binding to the real stdio worker. This is browser-harness evidence, not native WebView2 acceptance.
- Set `SITE_FACTORY_TEST_NODE` to the absolute trusted Node executable and `CARGO_TARGET_DIR` to a project-local build directory, then `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml`. Tests cover actual Node lifecycle, request rejection and compiled Tauri ACL dispatch.

Task10 normalizes local sites, jobs, operation admissions, revisions, site-scoped editing records, batches/rows and staged source/logo chunks in factory.sqlite. The runtime owns one shared connection; all factories accept that handle. SQLite extension loading is disabled, values are parameterized, durable transactions are synchronous and row work yields between admissions. Junction/symlink paths and competing controllers fail closed. Legacy sites/state.json,queue.json,revisions.json,editing.json are validated/migrated together and remain untouched after validated close/reopen. No2MB monolithic limit was raised.

For Task12, openLocalDatabase(root).snapshot(newPrivateDirectory) creates a consistent SQLite copy with VACUUM INTO. All staged sources/logos are inside that copy. The returned immutableRoots identify artifacts/checkpoints that can be copied afterward because current code never deletes their immutable objects. Returned mutableFiles identifies catalog-overrides.json; a full installation backup must quiesce the controller while capturing that external setting. Native credentials remain in their existing secret store and are not part of this DB export. Restore the DB in a fresh root, restore the declared immutable roots/settings, then reopen through openLocalDatabase for integrity/record validation; never overwrite an open controller. Task12 owns the user-facing backup/restore orchestration and retention.

Startup compatibility reads legacy registry state.json up to256MiB; existing queue/revision/editing private JSON documents keep their2,000,000-byte migration bounds. Reads allocate actual source size, validate all sources before one atomic install, and preserve originals. This one-time startup guard is separate from operational normalized storage. A synthetic72,783,817-byte/3000-record registry was migrated, reopened and checked against its unchanged SHA-256; run explicitly with SITE_FACTORY_LARGE_LEGACY_MIGRATION=1 if repeating that heavier fixture.
