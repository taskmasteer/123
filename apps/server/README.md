# Фоновая служба Site Factory на Windows VPS

Актуальный интерфейс — отдельное приложение. См. [инструкцию клиента](../client/README.md). Служба обслуживает только HTTPS API на TCP 9443; сайт-панель не размещается. Регистрация и вход — **логин и пароль, без email**. Первый аккаунт создаётся локально при пустой базе. Следующие аккаунты создаются по одноразовому коду, со сроком 20 минут. У всех участников одинаковые полные права.

При регистрации можно сохранить логин и пароль в выбранный пользователем файл. Это единственный момент экспорта пароля; в базе хранится scrypt-хеш. Логины сравниваются без учёта регистра, разрешены 3–32 символа: латиница, цифры, точка, дефис и подчёркивание.

## Что работает

- Серверная очередь, запросы к DeepSeek Flash, HTML/CSS/JS и проверки Chromium выполняются на Windows VPS, независимо от вкладки пользователя.
- Файлы, версии, задания, пользователи и настройки хранятся локально на сервере. PostgreSQL слушает только loopback.
- Создание сайта с упоминаемой ссылкой, отдельным рекомендательным блоком и проверкой его наличия. Для одиночного сайта сервер читает публичную страницу, если пояснение не введено. Для импорта предусмотрены столбцы `mentionedUrl` и `mentionedDescription`; пояснение следует указать в таблице.
- Приватный предпросмотр, AI-правки, принятие вариантов, визуальный выбор элемента через список, история принятых версий, чтение файлов и скачивание ZIP.
- CSV/XLSX, пакетная очередь, исправление строк, пауза и продолжение; библиотека оформления.
- Чёрно-белый интерфейс приложения на shadcn/ui, без настройки устройств, выбора режимов, ролей или модели изображений.

Готовая генерация сохраняется **черновиком**. В редакторе кнопка «Развернуть сайт» ставит отдельное долговечное задание: назначение IPv4, загрузка принятой версии на Linux, A-запись Namecheap, ожидание DNS, сертификат Let's Encrypt и HTTPS-проверка. Генерация сама по себе сайт не публикует. Защищённый домен и его поддомены исключены централизованной политикой. Поддержаны Namecheap и GoDaddy; доступ к зоне проверяется перед публикацией.

Linux-хост подготовлен: SSH-ключ с Windows DPAPI, пять дополнительных IPv4, Nginx и firewall. Проверен вход от SYSTEM. Доступны обновление, откат к успешной публикации и отдельная ручная замена IPv4. Подробности и ограничения — в [инструкции Linux-хоста](../../docs/operations/linux-host.md).

## Запуск и обслуживание

### Удобство и масштаб, версия клиента 0.3.0

Карточка сайта объединяет обзор, черновик, опубликованную версию и историю. Переключение разделов сохраняет состояние редактора. Массовый выбор поддерживает до 256 сайтов и сохраняется между страницами списка. Перед запуском проверяются доступ к DNS-зоне, конфликтующие записи, файлы и наличие IPv4; проверка не меняет DNS и не резервирует адреса. При запуске каждый сайт ставится в долговечную очередь с указанной версией. Изменившийся черновик или занятый адрес отклоняются повторной серверной проверкой. Результат показывается отдельно для каждого сайта; во время первоначальной постановки нужно дождаться окончания обработки в клиенте.

Исполнители работают одновременно максимум на четырёх серверах, последовательно внутри каждого сервера. Межпроцессные блокировки PostgreSQL предотвращают дублирование. Очистка истории получает исключительную блокировку, поскольку затрагивает предыдущие серверы сайта. Резервирование и остановка службы дожидаются всех активных исполнителей. Запросы Namecheap используют общий ограничитель частоты. Фактическая возможность размещения 256 сайтов зависит от назначенных адресов и ресурсов выбранного dedicated; IPv6-публикация требует отдельного расширения существующего IPv4-конвейера.

Обновления клиентов доступны в настройках после публикации ZIP через `scripts/publish-client-release.mjs`; порядок установки и смены сертификата описан в [инструкции клиента](../client/README.md).

Задача планировщика `SiteFactory-Control` запускается при старте Windows под SYSTEM. Она запускает PostgreSQL на 54329, затем API и исполнитель. Node закреплён отдельно от каталога обновлений Codex. Данные находятся в `.local-state/server`, Chromium — в `.local-state/browsers`, PostgreSQL — в `.local-state/tools/pgsql`.

```powershell
Get-ScheduledTask -TaskName SiteFactory-Control
Get-Content .local-state/server/server.log -Tail 30
```

Сборка и проверка:

```powershell
node scripts/build-server.mjs
node scripts/test-server.mjs
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.local-state/browsers'
node scripts/server-browser-smoke.mjs
```

`server-browser-smoke` использует отдельную временную базу и модель-фикстуру. `server-live-smoke.mjs` — отдельная **платная** проверка реального DeepSeek с уже настроенным ключом, без публикации и DNS. Оба удаляют только созданную ими тестовую базу; локальные результаты проверки сохраняются в `.local-state`.

Установка на новый Windows-хост: установить зависимости из lockfile, поместить PostgreSQL binaries в `.local-state/tools/pgsql`, установить Chromium через Playwright, выполнить `scripts/setup-windows-server.ps1` и `scripts/setup-native-connection.ps1 -PublicIPv4 <IPv4 VPS>`, собрать приложение и выполнить `scripts/install-windows-service.ps1`. Setup сохраняет существующую конфигурацию. Не переносить DPAPI-шифротекст на другую машину как способ переноса секретов: ключи и пароль БД привязаны к Windows-хосту.

## Граница безопасности

Сессии серверные, cookie HttpOnly/SameSite, Origin+CSRF для изменений, ограничение попыток входа, журнал действий. Пароли не восстанавливаются сервером. API-ключ шифруется Windows DPAPI LocalMachine; доступ к данным ограничен ACL. Предпросмотр работает в sandbox и по ограниченным подписанным ссылкам. Чтение упоминаемой страницы проверяет DNS и каждый redirect, запрещает приватные адреса и ограничивает время/размер.

HTTPS API доступен клиентам по TCP 9443. UI в службе отключён, PostgreSQL остаётся на loopback. Внешний провайдерский firewall может потребовать отдельного разрешения порта. MFA и восстановление забытого пароля через администратора пока не реализованы.

## Резервные копии и восстановление

В настройках приложения доступны создание полной копии, сохранение архива и отдельного ключа восстановления. Автоматически создаётся одна копия в сутки; хранятся последние семь проверенных архивов в каталоге данных `recovery`. Перед снимком закрывается допуск новых HTTP-операций, завершаются принятые запросы, приостанавливаются генерация и исполнители. После снимка они продолжают работу.

В копию входят полный PostgreSQL dump, файлы и версии, результаты проверок, каталоги оформления, исполняемый код и lockfile, конфигурация, пользователи, DNS- и SSH-секреты. Архив защищён AES-GCM и scrypt, проверяется перед выдачей. При восстановлении секреты повторно шифруются DPAPI нового Windows-хоста. Временные файлы с открытыми API/SSH/TLS-ключами не создаются.

**Сохраните архив и ключ вне VPS.** Копии на том же диске не защищают от потери сервера. Ключ можно сохранить повторно в приложении; он не входит в клиентский пакет. Архив не содержит Node/PostgreSQL/Chromium, `node_modules`, журналы и посторонние данные Windows. Linux восстанавливается отдельно; принятые версии сайтов входят в серверное хранилище и доступны для повторной загрузки.

На новом Windows-хосте сначала подготовьте обычную установку и локальный PostgreSQL по инструкции выше. Для проверки восстановления на текущем хосте работающую установку останавливать не требуется:

```powershell
.\scripts\restore-windows.ps1 -BackupFile D:\Backups\factory.sfbak -Destination C:\SiteFactoryRestore -Database sf_restore_pilot
```

Скрипт запросит ключ скрытым вводом и передаст его процессу через stdin. Требуются отсутствующий каталог назначения и новое имя БД с префиксом `sf_restore_`. Существующая база и установка не заменяются. Восстановление создаёт `data` и `source`, отзывает старые сессии и приглашения. Незавершённые публикации и настройки серверов требуют явного повтора; фоновые исполнители заблокированы флагом восстановления.

Для запуска восстановленной установки:

1. Выполните `npm ci --ignore-scripts` в восстановленном `source`: зависимости берутся из сохранённого lockfile.
2. Остановите старую задачу `SiteFactory-Control` и её процесс Node, проверив путь и принадлежность этой службе. Две управляющие установки одновременно запускать нельзя.
3. Из исходного установочного каталога выполните `scripts/install-windows-service.ps1 -DataDirectory C:\SiteFactoryRestore\data`. Служба использует восстановленный код и данные, а PostgreSQL и Chromium — из подготовленной установки. Для возврата остановите восстановленный экземпляр и установите задачу без DataDirectory.
4. На другом VPS проверьте публичный адрес и TLS-пакет клиента, Namecheap whitelist и ограничение `from=` SSH-ключей на Linux. При новом исходящем IP сначала восстановите SSH-доступ через альтернативный вход. Сохранённый отпечаток Linux автоматически не принимается заново.
5. После проверки откройте настройки приложения и нажмите «Продолжить после восстановления». До этого генерация, публикация и обслуживание не выполняются.

Монитор проверяет DNS, HTTP/HTTPS с маркером опубликованной версии и срок сертификата. Очередная проверка назначается через пять минут; время последней проверки видно в приложении. Результат старше десяти минут помечается устаревшим. Это проверка с управляющего VPS, а не независимый внешний монитор.
