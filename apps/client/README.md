# Site Factory — настольное приложение

Актуальная архитектура согласована 4 ноября 2026: отдельное приложение на компьютере каждого участника, общая база и генерация на Windows VPS. Сайт-панель не размещается. Electron содержит интерфейс shadcn/ui внутри пакета; Linux VPS нужны только для последующей публикации сайтов.

Первый аккаунт создаётся в приложении **на Windows VPS**: логин и пароль выбирает владелец. С чужого компьютера создать первого пользователя нельзя. После этого в настройках можно создать одноразовый ключ регистрации на **20 минут с момента выдачи**. Получатель запускает свою копию приложения, вводит ключ, после успешной проверки выбирает логин и пароль. Регистрация повторно проверяет срок и атомарно использует ключ. Просмотр формы не продлевает срок. Все аккаунты имеют одинаковые полные права.

## Сборка и запуск

```powershell
node scripts/build-server.mjs
node scripts/build-client.mjs
```

Готовый пакет: `.local-state/releases/Site Factory-win32-x64`. Запускать `Site Factory.exe`; другим пользователям передавать **весь пакет**, а не один EXE. Адрес VPS и открытый сертификат входят в пакет. API-ключей, паролей, базы и закрытого ключа сервера в нём нет. Отдельный домен для панели не требуется.

При первом запуске на VPS необходимо задать данные первого пользователя. Сохранение доступа открывает системное окно выбора файла. Пароль хранится в базе только в виде scrypt-хеша; сессия находится в памяти основного процесса клиента и не сохраняется в браузерное хранилище.

## Связь с VPS

Служба `SiteFactory-Control` обслуживает HTTPS API на TCP 9443. PostgreSQL доступен только локально. Корень HTTPS-службы и пути статических ресурсов возвращают 404: UI находится в клиенте. Первичная конфигурация TLS создаётся `scripts/setup-native-connection.ps1 -PublicIPv4 <адрес VPS>`; закрытый ключ и пароль PFX защищены DPAPI. Клиент проверяет цепочку, имя/IP сервера и закреплённый SHA-256 сертификата. При смене сертификата нужно выдать новый клиентский пакет.

Привилегированные действия доступны только главному окну через ограниченный IPC. Node.js отключён в интерфейсе и предпросмотре, включены sandbox, context isolation и CSP. Сгенерированный сайт не получает preload/API приложения. Права браузерных устройств запрещены. Проверка подключений с внешнего компьютера требуется отдельно: провайдерский firewall/NAT может ограничивать порт даже при корректной настройке Windows.

## Обновления начиная с 0.3.0

В настройках клиента доступны проверка версии и скачивание пакета. Архив передаётся через аутентифицированный HTTPS API с закреплённым сертификатом, порциями по 1 МиБ. Клиент проверяет размер, версию протокола и SHA-256 до замены выбранного файла. При обрыве или повреждении загрузки прежний файл сохраняется. Установка выполняется распаковкой в новую папку после закрытия приложения; старую папку можно оставить для возврата. Автоматической замены запущенного EXE нет.

После сборки клиента создайте `.local-state/releases/SiteFactory-Windows-x64.zip` из полного каталога пакета и выполните `node scripts/publish-client-release.mjs`. Публикуются архив с именем по хешу и атомарно заменяемый указатель текущей версии. Старые архивы сохраняются, чтобы уже начавшиеся загрузки не ломались. Не удаляйте их во время загрузок клиентов. Первый переход с 0.2.0 требует передачи нового пакета обычным способом.

Для смены адреса или TLS-сертификата подготовьте новые настройки через `setup-native-connection.ps1 -PublicIPv4 <новый IP> -RotateCertificate`, соберите и опубликуйте новый пакет, пока прежний API ещё доступен. Пользователи сначала скачивают пакет, затем оператор переключает службу и они запускают новую копию. Существующий клиент никогда автоматически не принимает неизвестный сертификат. При смене IP без явной ротации скрипт останавливается до изменения конфигурации.

## Проверки сценариев

`node scripts/test-server.mjs` проверяет регистрацию, срок ключа, гонку одновременных регистраций, повторное использование, запрет удалённого bootstrap и операции с сайтами. `scripts/client-smoke.mjs` запускает настоящий Electron с изолированной тестовой базой, TLS и моделью-фикстурой; проверяет два аккаунта, общий сайт, генерацию при закрытом клиенте, предпросмотр, системное сохранение файлов и ключи. Для Chromium-проверок задать `PLAYWRIGHT_BROWSERS_PATH=.local-state/browsers` (абсолютный путь).

Публикация, SSH-подготовка Linux, закрепление и замена IPv4, Namecheap/GoDaddy и HTTPS подключены. В настройках доступны полные резервные копии и сохранение ключа восстановления; в разделе серверов — обслуживание SSH и адресов. Перенос сайта, освобождение прежнего IPv4 и очистка истории находятся в редакторе сайта. Ключ регистрации предоставляет доступ ко всей фабрике; выдавать его только участникам, которым нужен полный доступ.
