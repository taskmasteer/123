# Серверная Site Factory на Windows

Статус: реализация этапов 1–3 разрешена пользователем 4 ноября 2026, без дополнительных подтверждений.

## Уточнение архитектуры 4 ноября 2026

Пользователь заменил браузерную панель на отдельные приложения на компьютерах участников. Общая база и генерация остаются на Windows VPS; размещается только HTTPS API, интерфейс включён в пакет Electron. Регистрация: первый локальный пользователь, затем проверка одноразового ключа на 20 минут перед формой логина/пароля. Актуальная реализация описана в apps/client/README.md. Ниже сохранён исходный проект первого этапа для истории.

## Граница исходного этапа

Центральная браузерная панель, приглашения и одна полная пользовательская роль, PostgreSQL и файлы на Windows VPS, DeepSeek, долговечная очередь, редактор и предпросмотр. Процессы независимы от открытой вкладки и RDP. Linux VPS, изменение DNS, покупка адресов и публичное открытие панели не входят в этот этап.

## Существующие части

Сохраняем PostgreSQL очередь с lease/fencing, версии, проверку HTML/Chromium, редактор, импорт, каталог шаблонов и файловые tools модели. Добавляем самостоятельный Node HTTP host вместо Vercel entrypoint. Локальная авторизация заменяет Supabase Auth в новом host; все приглашённые пользователи получают admin, без выбора роли. Прежние migration-файлы не переписываем.

## Хранение и запуск

PostgreSQL доступен только через loopback. Метаданные в PostgreSQL, immutable файлы в приватном каталоге установки. ObjectTransport получает файловую реализацию; HTTP uploads остаются проверенными по digest и lease. Независимый исполнитель использует существующий runWorker и API через внутрипроцессный transport, без токена в браузере. Автозапуск Windows и процедура перезапуска входят в поставку. Preview только loopback, пока не настроены публичный origin, TLS и обновления ОС.

## Авторизация

Регистрация и вход — только по логину и паролю, без email. Логин уникален без учёта регистра (3–32 символа: латиница, цифры, точка, дефис, подчёркивание). Первый аккаунт создаётся локально при пустой базе. Следующие регистрации требуют приглашения, привязанного к логину; код хранится хешем, ограничен сроком и одним использованием. Пароли хешируются memory-hard KDF, сессии отзываемые и серверные. Cookie HttpOnly/SameSite, Secure для HTTPS. Изменяющие запросы требуют правильный Origin и CSRF token. Ограничение попыток входа, журнал событий. API-ключ DeepSeek шифруется средствами Windows с ограничением ACL для Administrators и SYSTEM. Ключи не входят в Git, логи или checkpoint. Экспорт логина/пароля создаётся клиентом при регистрации; сервер пароль не восстанавливает. Предпросмотр sandbox, без доступа к сессии панели.

## Генерация

Фиксированные DeepSeek Responses endpoint и модель, без изображений. Сохраняем bounded tool loop, progress/checkpoint и повторные попытки. Упоминаемая ссылка входит в SiteInput, импорт, prompt, checkpoint binding и проверку результата. URL только HTTP(S) публичного сайта без credentials. Чтение целевой страницы ограничено размером/временем, DNS проверяется и адрес фиксируется для каждого перенаправления; приватные адреса запрещены. Недоступная страница требует пояснения пользователя, факты не выдумываем.

Проверенный первый результат сохраняется черновиком, автоматическая публикация выключена в серверной установке. UI не обещает DNS/HTTPS до отдельного этапа размещения.

## Домены

Точный запрещённый домен и все его поддомены отсекаются до любых внешних запросов. Проверка применяется к вводу, импорту, URL-ссылкам и будущим провайдерским адаптерам. Никаких запросов или внешних тестов к запрещённому домену. Адреса IPv4 впоследствии постоянные, с отдельной ручной заменой. Уникальный IPv6 не блокирует текущий этап.

## Приёмка

Приглашение → регистрация → экспорт доступа → ключ DeepSeek → создание сайта со ссылкой → закрытие браузера → результат после повторного входа. Проверяем перезапуск исполнителя, единую роль, защиту API/preview, сохранение редактора и импорта, отсутствие секретов в ответах, typecheck/build и локальный browser smoke. Реальный вызов модели отделяется в отчёте от fake transport тестов. Внешних изменений DNS/VPS не делаем.
