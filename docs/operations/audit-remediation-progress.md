# Результат исправлений полного аудита от 15 ноября 2026

Обновлено: 16 ноября 2026. Реестр охватывает все A01–A22 и дополнительные замечания.
Не следует читать его как гарантию отсутствия любых будущих ошибок или как подтверждение
доступности 256 реальных IP. Защищённый домен и его поддомены исключены из внешних действий.

## Основной реестр

| Пункт | Изменение и проверка | Остаточные условия |
|---|---|---|
| A01 — доступность API | Отдельный supervisor, проверка live, перезапуск дочернего процесса, ограниченные журналы. На рабочем Windows VPS принудительно остановлен дочерний процесс: появился новый PID, API вернулся к 200. | Зависит от доступности самого VPS. |
| A02 — отказ БД/worker | Повтор claim с backoff, supervisor исполнителя, безопасное завершение. Рабочая PostgreSQL была остановлена и запущена: ready изменился 503 → 200 без перезапуска API. | Отозванный доступ не повторяется бесконечно. |
| A03 — ожидание DeepSeek | Cooldown и число циклов повторов сохраняются в checkpoint; сервер возобновляет готовые задания. Есть конечный предел и понятная причина остановки. | Неопределённый уже отправленный запрос не повторяется вслепую. |
| A04 — старая копия/новый Linux | Сверка удалённых версий, адресов и монотонного порядка до снятия hold; импорт текущих файлов, запись истории и pin для последующего отката. Неизвестные IP, идентификаторы сайтов, отсутствующие в копии, и более старый Linux остаются на hold. Таймеры создаются сразу остановленными; повтор resume идемпотентен. | Потерянные после копии неизвестные сайты не восстанавливаются из воздуха; нужен достаточный RPO и внешний архив. |
| A05 — SSH | Обязательный доверенный SHA256 fingerprint; TOFU удалён. Проверены отказ неподтверждённого ключа и передача stdin. | Отпечаток берут из доверенной консоли провайдера. |
| A06 — привилегии | Рабочие API и PostgreSQL переведены с SYSTEM на LocalService. Runtime БД — отдельная роль без SUPERUSER/CREATEDB/чтения серверных файлов. Linux — отдельные units. | Операторские данные БД остаются необходимы для миграций/backup; автоматизация Linux всё ещё требует sudo/root. Это уменьшение привилегий, а не полная изоляция при RCE API. |
| A07 — мониторинг | Пакеты по 32 сайта, до 8 сайтов параллельно, независимые probes параллельны, тайм-ауты ограничены. Тест 256 сайтов с тайм-аутами завершает обход за 540 секунд, максимум 32 одновременных probe. | Нагрузочный стенд, не 256 выделенных провайдером адресов. |
| A08 — release gate | Общий unit/integration gate, обязательные server-тесты на временной PostgreSQL, исправлены старые fixtures и поиск Chromium. CI Windows/Linux, CLI install/restore и reference matrix. | Чистая Linux ОС и удалённый CI не запускались в этой Windows-сессии. |
| A09 — DNS-provider | Убран выбор по восьми пилотным доменам. Явное назначение в настройках; при одном подключённом провайдере он выбирается автоматически. DNS preflight до первого платного модельного запроса. | При двух провайдерах новый домен нужно однозначно назначить один раз. |
| A10 — GoDaddy | Пустая первая страница без totals допустима; неполный непустой ответ отвергается. | Production-права конкретного токена проверяются провайдером. |
| A11 — DNS-квоты | Общий сохраняемый limiter в PostgreSQL, учёт Retry-After. Namecheap интервал 11 секунд учитывает суточный предел, GoDaddy — 1,1 секунды. | Внешние запросы из других программ расходуют ту же квоту независимо от нашего limiter. |
| A12 — ZIP | Завершённые receipts не занимают активные слоты; bounded cache, идемпотентные chunk/commit, abort и клиентские повторы временных сбоев. | Архив должен укладываться в опубликованные лимиты. |
| A13 — очередь | Временная метка создания, стабильный порядок, пагинация генераций и публикаций, приоритет активных задач. | Таблица показывает актуальное задание сайта, история публикаций — отдельно. |
| A14 — генерация → публикация | Сохраняемые next_attempt/retry_count, автоматическое восстановление после временного сбоя постановки. | Постоянные конфликты не маскируются повтором. |
| A15 — резервирование | Проверяемая вторая копия зашифрованного архива в отдельный каталог/носитель, hash/size и отдельный статус; локальная копия сохраняется при ошибке replica. Реальные backup/restore проверены. | Внешний носитель пользователем ещё не задан. На рабочем сервере пока нельзя считать аварийное внешнее резервирование настроенным. |
| A16 — новый IP управления | На hold разрешено исправление SSH-подключения с аварийными credentials; повтор после ошибки не требует запуска публикаций. Обновляется ограничение источника, автоматический ключ проверяется. | Namecheap whitelist и аварийный доступ относятся к внешней инфраструктуре. |
| A17 — диагностика | Live/ready, состояние worker/копии/API-сертификата, безопасные operation/code/fingerprint/call-site логи без provider bodies и ключей, ротация. | Физическую недоступность VPS нужно отслеживать внешним монитором. |
| A18 — аккаунты | Смена пароля, список и отзыв других сессий, защита от гонки старого пароля, операторский reset-password. Email не требуется. | Все пользователи по-прежнему имеют одну общую суперроль — это требование продукта. |
| A19 — защита входа | Invite проверяется до дорогого scrypt; ограничены параллельные вычисления; очищаются истёкшие сессии, попытки и приглашения. | При сетевой атаке нужны и ограничения на уровне провайдера/сети. |
| A20 — доступность ZIP-сайта | Проверяется главная HTML-страница и маркер версии; ZIP валидирует ссылки на локальные ресурсы. Добавлены статические JSON/TXT/XML с сохранением запрета служебных package/config файлов. | Техническая доступность не равна проверке смысла текста/SEO. |
| A21 — UI | Фильтрация выполняется на сервере, старые ответы не заменяют новую выборку; контролируется polling и пагинация. Исправлены тексты о сервере и отсутствующем поле пояснения ссылки. | Полную перепись старых модулей не выполняли. |
| A22 — поставка | Обновлена уязвимая dev-цепочка asar/glob/minimatch; npm audit — 0. Независимые Ed25519 подписи клиента и API, проверка перед установкой. Есть updater, журнал замены, rollback, зашифрованная копия перед обновлением. | Authenticode требует отдельного сертификата издателя. Подпись manifest не является Authenticode; побитовая воспроизводимость архивов не заявляется. |

## Дополнительные замечания аудита

1. Dedicated/IPv6: безопасные ограничения текущего IPv4-профиля сохранены. Произвольный routed block, несколько IPv6 и AAAA ещё не реализованы. Нет фактического dedicated/IP-плана для проверки; это отдельное расширение инфраструктуры, а не подтверждённая возможность этого выпуска.
2. Linux PostgreSQL: отдельная служба; остановка API не убивает БД. API переживает временную недоступность БД. Требуется проверка полного установщика на чистой Linux ОС.
3. Обновление API: добавлены подписанный пакет, offline updater и wrappers Windows/Linux с проверкой готовности и возвратом кода. Переход ограничен явно проверенной совместимостью 0.5.0/0.6.0 → 0.6.0; неподдерживаемая схема отвергается. Реальный Windows CLI upgrade/rollback прошёл в отдельной установке с сохранением TLS и аккаунта.
4. www/canonical: не включались автоматически. Добавление alias меняет DNS, сертификат и маршрутизацию; прежние договорённости не давали поручения молча включить www всем доменам. Текущий выпуск публикует apex.
5. Составные зоны: Namecheap получает SLD и оставшийся TLD, включая co.uk; добавлен контрактный тест. Право управления корневой зоной подтверждает API провайдера.
6. Статические файлы: robots.txt/sitemap.xml/JSON поддерживаются API и текущим Linux helper. До 100 файлов, 2 МБ на файл, 10 МБ суммарно, ZIP до 11 МБ. Helper берётся из установленного API, а не из старой восстановленной библиотеки.
7. Качество: проверены все включённые reference templates на desktop/mobile; регрессионная матрица сохранена. Новые платные генерации всей библиотеки в этой сессии не запускались. Достоверность текста, права на референсы и SEO автоматическими тестами не гарантируются.
8. Бюджеты: сервер атомарно резервирует консервативный объём по заданию и пачке; счётчик переживает перезапуск. Лимит настраивается environment и не выдаётся за фактическую стоимость провайдера.
9. Упоминаемая ссылка: ошибка больше не отправляет пользователя в удалённое поле; предлагается проверить/заменить URL. Недоступная страница не превращается в подтверждённое описание.
10. TLS API: есть предупреждение заранее и проверенный выпуск нового файла подключения. Перекрытие двух доверенных сертификатов пока отсутствует: ротация требует планового окна и передачи файла клиентам.
11. Один управляющий узел: реальное восстановление и перенос секретов проверены, но внешний носитель ещё не подключён. RPO при ежедневном backup — до суток плюс незавершённые операции; сетевой перенос/RTO зависят от объёма и доступа к новому серверу. HA-кластер не заявляется.
12. Сопровождение: выделены отдельные модули для бюджетов, DNS limiter, recovery reconciliation, диагностики, подписи/обновления и настроек аккаунта. Legacy local/cloud сохранены с тестами; тотальная перепись и удаление legacy не выполнялись.

## Подтверждённые проверки

- Unit: 61 файлов, 500 passed, 25 skipped; общий набор без ошибок.
- Integration: 21 файлов, 124 passed, 3 skipped. Включены объём 256 сайтов, rollback/fencing/retention и права. Старый extended benchmark на 5000 остаётся опцией SITE_FACTORY_EXTENDED_SCALE=1.
- Server: 11 файлов, 71 passed в заключительном изолированном прогоне, включая начальный recovery hold.
- Дополнительно: 9 regression-тестов и отдельный DB-тест импорта удалённой версии прошли. На реальном Linux прочитаны только ID каталогов: 6, все известны реестру; содержимое сайтов не изменялось.
- Native Electron smoke: вход, приглашения, сохранение/скачивание, TLS pin, подписанное обновление, отклонение повреждённого пакета, генерация и автоматическая публикация при закрытом клиенте — passed.
- Настоящая отдельная CLI-установка: HTTPS, сохранение аккаунта/файлов, backup/restore с hold, смена сертификата, подписанное API-обновление, откат и повторный запуск — passed.
- Reference matrix: все включённые референсы, ширины 375/390/700; без горизонтального переполнения и без изменения desktop геометрии.
- Python Linux publisher: 3 теста passed; SSH pin/key/stdin: passed; подписи и прерванная замена кода: passed.
- Рабочий Windows VPS: API и БД LocalService; ограниченная runtime DB роль подтверждена. Проверены принудительное завершение дочернего API и временный отказ БД. После восстановления live=200, ready=200, /api/sites без сессии=401.
- Перед изменением служб создана полная зашифрованная копия (около 293 МиБ). Ключ восстановления в документацию не включался.

Числа из разных наборов не складываются: наборы пересекаются. Пропущенные проверки
с реальными внешними провайдерами не объявлены выполненными. CI на GitHub не запускался
без публикации текущих изменений; чистый Linux install остаётся отдельной проверкой окружения.
